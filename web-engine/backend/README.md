# Omoluabi Web Engine — backend preview

An independently deployable, private editorial workspace for Omoluabi. It uses the governance-first browser prototype in `../app/` as its interaction reference and adds persistent records, member access, evidence links, temporary intake, and publication controls.

## What is implemented

- Email sign-in links backed by Supabase Auth; access is denied unless an administrator has added the user as a workspace member.
- Investigation records, source register, checkable claims, claim-to-source evidence links, review states, and recent record history.
- Temporary intake with a 72-hour expiry. Intake stays separate from permanent research records until a person reviews and promotes it.
- Database row-level security on every table. Audit history is generated by database triggers and has no user-facing update/delete path.
- A publication guard in PostgreSQL. Only a designated publisher can change status. Public status additionally requires cleared investigation and source consent, completed risk and accessibility review, at least one source and claim, reviewed claims with linked evidence, and no disputed claims.
- No model is connected. The system does not decide truth or publish automatically.

## Run locally

Requirements: Node.js 20 or newer, npm, and a Supabase project.

1. Copy `.env.example` to `.env.local` and set the project URL, anon/publishable key, and site URL.
2. In the Supabase SQL editor, apply `supabase/migrations/202610230001_initial_backend.sql` (or link the project and run `supabase db push`).
3. Invite the initial publisher from Supabase Authentication, then add that user's UUID:

   ```sql
   insert into public.workspace_members (user_id, role)
   values ('AUTH_USER_UUID', 'publisher');
   ```

4. Run `npm install`, `npm run dev`, then open `http://localhost:3000`.

Add later members with role `editor`, `reviewer`, or `publisher` using Supabase Auth's invite flow. Set the Auth redirect allow list to include the local URL and the production URL ending in `/auth/confirm`. Disable public sign-ups; access remains limited by `workspace_members` even if an uninvited account exists.

## Deploy

Import `ukadike/omoluabi` into Vercel and set the project Root Directory to `web-engine/backend`. Add all three variables from `.env.example` in Vercel for Preview and Production. Apply the SQL migration to the intended Supabase project, invite the initial publisher, and verify sign-in and the publication gate on a private preview before enabling production access.

GitHub hosts the source. Supabase provides the database, Auth, and row-level security. Vercel runs the Next.js app. Do not put a Supabase service-role key in this app or in Git; the server uses the public anon/publishable key with each signed-in user's session.

## Current release boundary

The deployable code and migration are public in this repository. A live service needs an owner-controlled Supabase project and Vercel project/environment variables. No credentials or user data are stored in this repository. Public article export, file uploads, team/workspace separation, and conflict-safe offline sync are follow-on work; the existing static prototype remains at `../app/`.
